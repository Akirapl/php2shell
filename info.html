O projekcie

Kto stoi za tą stroną, jak zgłaszać poprawki, jak śledzić zmiany i co zostanie, gdy relacja na żywo się skończy.

Kto to robi

To niezależny, niekomercyjny projekt o charakterze obronnym i dziennikarskim. Prowadzi go użytkownik GitHuba @Akirapl.

  • Materiały powstają z pomocą AI, ale każdy fakt jest sprawdzany ze wskazanym źródłem i oznaczony jako potwierdzone, doniesienie lub szacunek.
  • Projekt nie jest powiązany z projektem PHP, Wiz, Calif ani żadnym dostawcą.
  • Celowo nie publikujemy kodu exploitów ani instrukcji ataku. Przyczyny luk opisujemy tylko na poziomie oficjalnych advisory.

Gdzie pisać

Wszystkie zgłoszenia przyjmujemy przez GitHub Issues. Są tam gotowe szablony:

  • Poprawka — zacytuj fragment, który jest błędny, i podaj źródło.
  • Nowe źródło — link i krótko, co wnosi.
  • Tłumaczenie — błąd lub niezręczność w wersji PL, EN albo DE.

⚠️ Nigdy nie wpisuj w zgłoszeniu szczegółów exploita.

  • Luka w samym PHP? Zgłoś ją bezpośrednio zespołowi PHP przez formularz prywatnego zgłoszenia na GitHubie (php/php-src), zgodnie z ich polityką bezpieczeństwa. Jeśli nie możesz użyć formularza: security@php.net. My nie przyjmujemy takich zgłoszeń.
  • Problem z treścią tej strony (np. coś zdradza za dużo)? Otwórz issue bez wrażliwych szczegółów — zasady opisuje SECURITY.md.

Przejrzystość

Historia zmian jest publiczna. Każda poprawka ma datę i jest widoczna:

  • Historia commitów
  • Historia kompendium: PL · EN · DE
  • Kanał Atom ze zmianami — do czytnika RSS
  • CHANGELOG.md — opisowy dziennik zmian
  • data/facts.json — wszystkie fakty ze źródłami

Co zostanie na koniec

Plan na zakończenie relacji (jeszcze nie wykonany):

  1. Gdy przez ok. 14 dni nie będzie istotnych nowości albo gdy prowadzący tak zdecyduje, centrum na żywo zostanie zamrożone jako statyczne archiwum z banerem „zarchiwizowano dnia…”.
  2. W repozytorium pojawi się ostateczny tag wydania.
  3. facts.json zostanie zamrożony jako końcowy zbiór danych.
  4. Kompendium zostanie jako stały dokument; późniejsze poprawki będą datowane.
  5. Kluczowe źródła zostaną zabezpieczone jako kopie w Wayback Machine.
  6. Po ostatnim okresie na poprawki repozytorium na GitHubie zostanie zarchiwizowane (tylko do odczytu).

About this project

Who runs this page, how to send corrections, how to follow every change, and what stays once live coverage ends.

Who we are

An independent, non-commercial project with a defensive, journalistic purpose, maintained by GitHub user @Akirapl.

  • It is prepared with AI assistance, but every fact is checked against a cited source and labelled confirmed, reported or estimate.
  • Not affiliated with the PHP project, Wiz, Calif or any vendor.
  • No exploit code and no attack instructions, by design. Root causes are covered only at the level of the official advisories.

How to reach us

Everything goes through GitHub Issues, which has templates for:

  • Corrections — quote the wrong passage and give a source.
  • New sources — the link and a line on what it adds.
  • Translation fixes — errors or awkward wording in PL, EN or DE.

⚠️ Never post exploit details in an issue.

  • Found a vulnerability in PHP itself? Report it straight to the PHP project through its private GitHub reporting form (php/php-src), as set out in its security policy. If you can’t use the form: security@php.net. We don’t handle those reports.
  • Worried about something on this site (e.g. it reveals too much)? Open an issue without the sensitive detail — see SECURITY.md.

Transparency

The edit history is public. Every correction is dated and visible:

  • Commit history
  • Case study history: PL · EN · DE
  • Atom feed of changes — for your feed reader
  • CHANGELOG.md — a readable change log
  • data/facts.json — every fact with its source

What stays at the end

The plan for wrapping up (not carried out yet):

  1. Once there have been no material developments for about 14 days, or the maintainer decides so, the live center will be frozen into a static archive with an “archived on …” banner.
  2. A final release tag will be created in the repository.
  3. facts.json will be frozen as the final dataset.
  4. The case study will remain as the permanent document, with any later corrections dated.
  5. Key sources will be preserved as Wayback Machine snapshots.
  6. After a final corrections window, the GitHub repository will be archived as read-only.

Über das Projekt

Wer hinter dieser Seite steht, wie Sie Korrekturen melden, wie sich jede Änderung nachverfolgen lässt und was bleibt, wenn die Live-Berichterstattung endet.

Wer dahintersteht

Ein unabhängiges, nichtkommerzielles Projekt mit defensivem, journalistischem Anspruch, betreut vom GitHub-Nutzer @Akirapl.

  • Die Inhalte entstehen mit KI-Unterstützung; jede Angabe wird jedoch anhand einer genannten Quelle geprüft und als bestätigt, gemeldet oder Schätzung gekennzeichnet.
  • Keine Verbindung zum PHP-Projekt, zu Wiz, Calif oder einem anderen Anbieter.
  • Bewusst kein Exploit-Code und keine Angriffsanleitungen. Ursachen werden nur so tief beschrieben wie in den offiziellen Advisories.

Kontakt

Alles läuft über GitHub Issues mit Vorlagen für:

  • Korrekturen — die fehlerhafte Stelle zitieren und eine Quelle angeben.
  • Neue Quellen — Link plus ein Satz, was sie beiträgt.
  • Übersetzungen — Fehler oder holprige Formulierungen auf PL, EN oder DE.

⚠️ Bitte niemals Exploit-Details in ein Issue schreiben.

  • Eine Lücke in PHP selbst gefunden? Melden Sie sie direkt dem PHP-Projekt über dessen privates Meldeformular auf GitHub (php/php-src), wie in der Sicherheitsrichtlinie beschrieben. Falls das Formular nicht nutzbar ist: security@php.net. Wir selbst nehmen solche Meldungen nicht entgegen.
  • Bedenken zu Inhalten dieser Seite (z. B. zu viele Details)? Eröffnen Sie ein Issue ohne die heiklen Einzelheiten — siehe SECURITY.md.

Transparenz

Der Änderungsverlauf ist öffentlich. Jede Korrektur ist datiert und nachvollziehbar:

  • Commit-Verlauf
  • Verlauf der Fallstudie: PL · EN · DE
  • Atom-Feed der Änderungen — für Ihren Feedreader
  • CHANGELOG.md — lesbares Änderungsprotokoll
  • data/facts.json — alle Fakten mit Quelle

Was am Ende bleibt

Der Plan für den Abschluss (noch nicht umgesetzt):

  1. Gibt es etwa 14 Tage lang keine wesentlichen Neuigkeiten oder entscheidet der Betreuer so, wird das Live-Center als statisches Archiv mit dem Hinweis „archiviert am …“ eingefroren.
  2. Im Repository wird ein finaler Release-Tag gesetzt.
  3. facts.json wird als endgültiger Datensatz eingefroren.
  4. Die Fallstudie bleibt als dauerhaftes Dokument bestehen; spätere Korrekturen werden datiert.
  5. Wichtige Quellen werden als Snapshots in der Wayback Machine gesichert.
  6. Nach einer letzten Korrekturphase wird das GitHub-Repository schreibgeschützt archiviert.
