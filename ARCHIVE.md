# What remains at the end / Co zostaje na końcu / Was am Ende bleibt

Status: plan, as of 21.10.2026. These steps are not carried out.

Stan: plan, 21.10.2026. Tych kroków nie wykonano.

Stand: Plan, 21.10.2026. Diese Schritte sind nicht ausgeführt.

Live center / Centrum na żywo / Live-Center: <https://akirapl.github.io/php2shell/>

## Polski

Pokrycie na żywo kończy się, gdy przez około 14 dni nie ma istotnych nowych ustaleń, albo gdy tak zdecyduje właściciel.

Plan na ten moment:

1. Centrum na żywo zostaje zamrożone jako statyczny snapshot archiwum, z widocznym banerem „archived on” i datą.
2. Powstaje końcowy tag wydania, na przykład `v2.0-final`, razem z notami wydania.
3. `data/facts.json` zostaje zamrożony jako końcowy zbiór danych.
4. Studium przypadku zostaje trwałym dokumentem. Nadal może przyjmować datowane korekty. Każda korekta jest wpisywana do [CHANGELOG.md](CHANGELOG.md).
5. Kluczowe źródła zostają zachowane jako snapshoty Wayback Machine i wypisane w indeksie dowodów w tym repozytorium. Indeksu jeszcze nie ma.
6. Repozytorium na GitHubie przechodzi w stan archiwum tylko do odczytu dopiero po końcowym oknie na korekty.

## English

Live coverage ends when there are no material new developments for about 14 days, or when the owner decides that it has ended.

The plan for that point:

1. The live center is frozen into a static archive snapshot, with a visible “archived on” banner and a date.
2. A final release tag is cut, for example `v2.0-final`, with release notes.
3. `data/facts.json` is frozen as the final dataset.
4. The case study stays as the permanent document. It may still receive dated corrections. Each correction is listed in [CHANGELOG.md](CHANGELOG.md).
5. Key sources are preserved as Wayback Machine snapshots and listed in an evidence index in this repository. That index does not exist yet.
6. The GitHub repository is archived read-only only after a final corrections window.

## Deutsch

Die Live-Berichterstattung endet, wenn es etwa 14 Tage lang keine wesentlichen neuen Entwicklungen gibt, oder wenn der Eigentümer das Ende festlegt.

Der Plan für diesen Zeitpunkt:

1. Das Live-Center wird als statischer Archiv-Snapshot eingefroren, mit einem sichtbaren Banner „archived on“ und einem Datum.
2. Ein finaler Release-Tag wird gesetzt, zum Beispiel `v2.0-final`, mit Release-Notes.
3. `data/facts.json` wird als finaler Datensatz eingefroren.
4. Die Fallstudie bleibt das dauerhafte Dokument. Sie kann weiterhin datierte Korrekturen erhalten. Jede Korrektur wird in [CHANGELOG.md](CHANGELOG.md) eingetragen.
5. Zentrale Quellen werden als Wayback-Machine-Snapshots erhalten und in einem Nachweisindex in diesem Repository aufgelistet. Diesen Index gibt es noch nicht.
6. Das GitHub-Repository wird erst nach einem abschließenden Korrekturfenster schreibgeschützt archiviert.
